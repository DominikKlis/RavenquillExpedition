Modified (2026-11-15): libs\HereBeDragons\HereBeDragons-Pins-2.0.lua (MINOR unchanged, 17). The world map
pin pool and data provider are registered on WorldMapFrame only when the first world map icon is added, not at
load; the provider's methods do nothing until then. Reason: a registered provider runs addon code inside
Blizzard's secure map-show path, which tainted it (ADDON_ACTION_BLOCKED 'Button:SetPassThroughButtons()' for
Blizzard's quest pins). This addon uses only the minimap part; its world map pins are drawn by Pins.lua.
Modified (2026-11-15): both files register under private LibStub names ("HereBeDragons-2.0-RQE",
"HereBeDragons-Pins-2.0-RQE"), like GuildMap does with "-gm". Reason: with the shared name, LibStub keeps one copy
for all addons (RXPGuides ships the same name and version); our calls then wrote into the copy whose world map provider
other addons use, and Blizzard blamed this addon for the blocked SetPassThroughButtons (verified in game).
Every change is marked "RavenquillExpedition_Map modification" in the file.
